# 04. async 函数返回 Promise

## 题目

在处理异步操作时，`async` 关键字修饰的函数其返回值总是？

- A. 一个 `boolean` 值，表示函数是否执行成功
- B. 一个 `Promise` 对象
- C. `undefined`，因为它是异步的，没有返回值
- D. 一个字符串类型的数据

## 正确答案

- `B. 一个 Promise 对象`

## 一句话理解

只要函数前面写了 `async`，它的返回值就一定会被包装成一个 `Promise`。

## 最小例子

```TypeScript
async function add() {
  return 123
}
```

表面上看像是返回 `123`，但真正返回的更接近：

```TypeScript
function add() {
  return Promise.resolve(123)
}
```

所以 `add()` 的返回值不是普通数字，而是一个 `Promise`。

## 执行链路

```TypeScript
async function getName() {
  return 'Tom'
}
```

可以按这个顺序理解：

1. 调用 `getName()`
2. 函数内部写的是 `return 'Tom'`
3. 但因为有 `async`
4. `'Tom'` 不会直接返回给外部
5. 它会被自动包装成 `Promise.resolve('Tom')`
6. 所以最后返回的是 `Promise<string>`

## 每个选项为什么错

### A. 一个 boolean 值，表示函数是否执行成功

错在哪里：

- `async` 不会把结果变成 `true` 或 `false`
- 异步函数返回的核心是“一个未来会有结果的 Promise”
- 成功还是失败，不是靠 boolean 表示，而是靠 Promise 的状态表示

为什么会误选：

- 很多人把“异步是否成功”理解成“返回 true / false”
- 但 Promise 不是这样设计的

改成什么才对：

- 改成“返回一个 Promise 对象，成功或失败通过 Promise 状态体现”才对

### B. 一个 Promise 对象

这是正确项。

为什么对：

- `async function foo() { return 1 }`
- 本质上接近 `function foo() { return Promise.resolve(1) }`
- 所以返回值一定是 Promise

### C. undefined，因为它是异步的，没有返回值

错在哪里：

- 异步函数不是“没有返回值”
- 即使你没显式写 `return`
- 它也会返回一个 `Promise`

例如：

```TypeScript
async function foo() {
}
```

这更接近：

```TypeScript
function foo() {
  return Promise.resolve(undefined)
}
```

所以它不是直接返回 `undefined`，而是返回“解析结果为 `undefined` 的 Promise”。

改成什么才对：

- 改成“返回一个解析值为 `undefined` 的 Promise”才对

### D. 一个字符串类型的数据

错在哪里：

- `async` 不会规定返回值一定是字符串
- 你可以返回数字、对象、数组、字符串，甚至不写返回值
- 真正固定的是“外层一定是 Promise”，不是“里面一定是字符串”

为什么会误选：

- 题目里常用字符串示例，比如 `return "完成"`
- 但那只是示例数据，不是语法规则

改成什么才对：

- 改成“返回一个 Promise，Promise 里面可以包裹字符串等具体数据”才对
