[answer]
1.因为
2 - **Thought**：模型根据当前问题和已有信息进行分析，判断下一步该做什么。
- **Action**：模型决定采取某个动作，通常表现为**调用某个工具，并给出调用参数**。
- **Observation**：工具执行 Action 后返回的**执行结果**，模型再根据这个结果继续推理。
3.在 ReAct 智能体范式中，将 **Observation****（观察结果）** 整合并追加到 **History****（历史上下文）** 中，是整个智能体能够运转并持续逼近目标的灵魂所在。
其核心原因可以归结为以下四个维度：
- **形成“感知-思考-行动-观察”的控制闭环**：这是形成闭环的最关键步骤。大语言模型本身是无状态的（每次调用都是独立的），如果不把工具执行后的 `Observation` 连同之前的 `Action` 一起添加回历史记录中，系统就无法为下一轮循环组装出更新后的上下文。
- **让大模型拥有“看”到行动反馈的眼睛**：通过将 `Observation` 追加到历史记录中，智能体在下一轮生成提示词并调用 LLM 时，模型才能在上下文里“看到”上一步行动所产生的真实结果。只有知道了上一步做得好不好、拿到了什么数据，模型才能据此展开**新一轮符合客观事实的思考和规划**。
- **赋予智能体“动态规划与即时纠错”的能力**：与一次性生成完整计划的范式不同，ReAct 采用的是“走一步，看一步”的策略。模型需要根据每一步从外部世界实时获取的 `Observation`，来动态调整后续的 `Thought` 和 `Action`。例如，如果历史记录中的上一步搜索结果不理想，模型在这一步就能在 `Thought` 中反思，并输出一个新的搜索词重新尝试。
- **让“推理”与“事实”产生协同效应**：在数学表达上，智能体在当前步 t 的决策，是基于初始问题 q 以及之前**所有的“行动-观察”历史轨迹** ((a1​,o1​),…,(at−1​,ot−1​)) 共同决定的。这种机制使得**推理（Thought）让行动更具目的性，而行动产生的观察（Observation）则为推理提供了事实依据**，从而彻底避免了模型仅凭自身知识库产生的“事实幻觉”。

如果缺少了将 `Observation` 填回 `History` 的步骤，智能体就会失去外部世界的反馈，重新退化为无法纠错、无法感知外部状态的“单向思考”模式
