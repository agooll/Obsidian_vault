## 二、8 月底项目范围

项目暂定名：

## EvidenceAgent——带证据引用的技术资料调研助手

### 核心场景

把本地 `HelloAgent/章节/` 作为第一批知识库。用户可以提出：

- “ReAct 与 Plan-and-Solve 的差异是什么？”
- “RAG、Memory、上下文工程分别解决什么问题？”
- “比较 AutoGen、AgentScope、CAMEL、LangGraph 的适用场景。”
- “根据第 7、8、9 章，给出一个 Agent 项目的架构方案。”

系统需要：

1. 判断问题是否需要检索；
2. 将复杂问题拆为子问题；
3. 检索本地 Markdown 文档；
4. 调用文档检索、文件读取、计算等工具；
5. 生成带文件名和章节引用的回答；
6. 在证据不足时拒绝编造；
7. 记录一次任务的计划、工具调用和结果；
8. 使用固定评测集衡量检索和回答效果。

### 8 月底必须完成

- [ ] 本地 Qwen 或一个可替换的 LLM Client；
- [ ] 一个自己实现的 ReAct/工具调用循环；
- [ ] 至少 3 个工具：文档列表、文档读取、知识检索；
- [ ] Markdown 文档切分、索引和检索；
- [ ] 回答包含真实文件路径或章节引用；
- [ ] 至少 30 条固定评测样例；
- [ ] 检索命中率、引用正确率、任务成功率、平均延迟；
- [ ] 一个简单的 Streamlit 或 FastAPI 演示入口；
- [ ] README、架构图、演示 GIF/视频；
- [ ] 三条基于真实指标的简历描述。

### 8 月明确不做

- 完整 Memory 系统；
- MCP、A2A、ANP；
- Agentic RL；
- 复杂多智能体系统；
- 完整 BFCL 和 GAIA 官方评测；
- 前后端分离的大型网页；
- 为了好看而增加的复杂 UI；
- 与项目目标无关的十几个工具。

这些内容不是不学，而是放到 9 月，避免 8 月变成赶工和复制代码。

## 四、每日固定执行方式

### 工作日

- 20 分钟：闭卷回忆前一天；
- 50～60 分钟：阅读指定文件和小节；
- 80～90 分钟：独立写代码；
- 20 分钟：整理笔记和 Git 提交。

### 周末

- 40 分钟：本周闭卷复盘；
- 80～100 分钟：阅读；
- 180 分钟：项目开发和调试；
- 40 分钟：测试、整理 README、提交代码。

### 每日笔记模板

保存到 `notes/daily/YYYY-MM-DD.md`：

```markdown
# 今日学习文件与小节

## 核心执行流程

## 为什么这样设计

## 我独立写了什么

## 遇到的错误、根因和修复

## 今天仍然不能独立解释的内容

## 明天开始前要回答的三个问题
```

当天没有代码、笔记、测试或项目产出中的任何一项，就不算完成。

## 十、判断自己是否真的“能投”

满足以下条件即可投递，不需要等到所有知识学完：

- 能在 5 分钟内讲清项目；
- 能独立修改一个工具或检索策略；
- 知道一次错误发生在哪一层；
- 简历指标可重复验证；
- 仓库别人能够运行；
- 能诚实说明项目尚未实现的部分；
- 被问到 Memory、MCP、RL 时，可以回答基本概念并明确它们是 9 月学习项。

这条路线的目的不是让你在 8 月底显得什么都会，而是让你有一个真实做过、能够继续迭代、经得起基础追问的项目。
